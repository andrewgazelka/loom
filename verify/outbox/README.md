# Verified outbox delivery: Rust to Lean, end to end

A pure Rust core of Loom's outbox delivery (`rust/src/lib.rs`), translated to
Lean by Charon and Aeneas, with machine-checked proofs that it delivers each key
exactly once under any sequence of pumps, acks, crashes, and resets.

The protocol mirrors `crates/loom-actor/src/pump.rs` (inject the row, then mark it
delivered in a second transaction) and `crates/loom-actor/src/reset.rs` (a new
incarnation copies the `applied:` receipts). A crash between the two transactions
leaves the row undelivered, so the pump sends it again; the receipts turn the second
injection into a no-op.

## Layout

| File | Role |
|---|---|
| `rust/src/lib.rs` | The code under proof: `step(&mut World, Event)`, no IO, no async |
| `lean/Outbox/Generated/` | Aeneas output from the Rust. Regenerated by `check.sh`, never edited |
| `lean/Outbox/Spec.lean` | Reference model on Lean lists; the `exactly_once` proof; the planted bug refuted |
| `lean/Outbox/Check.lean` | A TLC-style bounded checker: every trace to depth 5, prints the shortest violation |
| `lean/Outbox/Refinement.lean` | Proof that the generated Rust computes `Spec.step`; `rust_step_exactly_once` |
| `lean/Axioms.lean` | Prints the axioms each headline theorem uses; `sorryAx` must not appear |

## What is proved

- `Spec.exactly_once`: from a fresh world, for every event list, the handled log has no duplicates.
- `Spec.pump_ack_delivers`: a pump followed by an ack marks an undelivered row delivered.
- `Spec.badReset_breaks_exactly_once`: with a reset that drops receipts, the trace
  `[pump 0, reset, pump 0]` handles key 7 twice.
- `Refinement.step_refines`: when the Rust arithmetic cannot overflow (`Fits`: room to
  push one receipt, generation below `U64.max`), `outbox_core.step` returns `ok w'` and
  `absW w' = Spec.step goodReset (absW w) (absE e)`.
- `Refinement.rust_step_exactly_once`: the invariant, and so no duplicate handling,
  holds after every Rust step.

Negative control (2026-09-22): making the Rust `reset` clear `applied` fails
`reset_spec` at `Refinement.lean:100` (unsolved goals); restoring it passes.

## What is trusted

- Charon and Aeneas translate the Rust faithfully.
- Lean's kernel.
- The shell that loads rows, calls `step`, and writes the result in one Turso
  transaction; it does not exist yet. A property test comparing the shell's
  database with `absW` after random operations is the next step.

## Checker trap met while building this

`Check.lean` first searched for traces that break the internal invariant `Inv`
(handled log equals receipts). It reported `[pump 0, reset]`, a state that breaks
`Inv` but has handled nothing twice. A bounded checker should test the observable
property; the invariant is a proof device.
